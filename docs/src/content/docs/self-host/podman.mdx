The [Docker & Compose](/self-host/docker/) guide covers the images, the volume requirement, upgrades, and most of the troubleshooting; this page is what is different under Podman.

## Rootless

Rootless Podman is fine: the app listens on port **3000**, which is above 1024, so an unprivileged user can bind it. If you remap to a port **below 1024**, rootless needs `sysctl net.ipv4.ip_unprivileged_port_start=0` (or run privileged).

## SELinux

On SELinux hosts (Fedora, RHEL), append `:z` (shared) or `:Z` (private) to **bind mounts**:

```bash
podman run -d --name galene \
  -v /var/lib/galene:/app/data:Z \
  -p 3000:3000 \
  galene:app
```

Named volumes are relabeled by Podman automatically and need no suffix.

## podman-compose

The same `docker-compose.yml` works with [`podman-compose`](https://github.com/containers/podman-compose):

```bash
podman-compose up -d
```

## Quadlet

For a systemd-managed container, a quadlet unit is the cleanest path. For a rootless user, put this in `~/.config/containers/systemd/galene.container` (for a system service, `/etc/containers/systemd/` instead):

```ini
[Container]
Image=ghcr.io/galene-finance/galene:latest
ContainerName=galene
PublishPort=3000:3000
Volume=galene_data:/app/data
Environment=GALENE_COOKIE_SECURE=0
HealthCmd=["bun", "-e", "fetch(\"http://localhost:3000/health\").then(r => process.exit(r.status === 200 ? 0 : 1)).catch(() => process.exit(1))"]
HealthInterval=30s
HealthTimeout=5s
HealthRetries=3
HealthStartPeriod=15s

[Service]
Restart=always

[Install]
WantedBy=default.target
```

Then enable and start it:

```bash
systemctl --user daemon-reload
systemctl --user enable --now galene.container
journalctl --user -u galene.container -f
```

Notes:

- The named volume `galene_data` is created by Podman on first start and relabeled automatically. If you prefer a bind mount, use `Volume=/path/on/host:/app/data:Z` (`:Z` on SELinux hosts).
- `GALENE_COOKIE_SECURE=0` is for plain HTTP; set it to `1` behind a TLS-terminating proxy ([Reverse proxy](/self-host/reverse-proxy/)).
- For a system unit, use `WantedBy=multi-user.target` and `systemctl enable --now galene.container` (without `--user`).

## Healthcheck

CI publishes the image in OCI format. Docker applies the Dockerfile `HEALTHCHECK`. Podman applies that instruction only to Docker-format images, so under Podman and Quadlet the image check never runs. The image has `bun` and `node`, and no `curl` or `wget`.

Add these keys to the quadlet `[Container]` section (they are already in the unit above). The probe calls `http://localhost:3000/health` on the port the process listens on inside the container (`PORT` and `EXPOSE` are **3000**). `PublishPort` only chooses the host port; a mapping such as `5174:3000` still uses `localhost:3000` here.

```ini
HealthCmd=["bun", "-e", "fetch(\"http://localhost:3000/health\").then(r => process.exit(r.status === 200 ? 0 : 1)).catch(() => process.exit(1))"]
HealthInterval=30s
HealthTimeout=5s
HealthRetries=3
HealthStartPeriod=15s
```

:::warning
The shell-string form (`HealthCmd=bun -e "..."`) loses its inner quotes through Quadlet and systemd, and the container stays unhealthy. Use the JSON array form above.
:::

Reload and restart, then run the check by container name (`ContainerName` in the unit; `galene` in the example):

```bash
systemctl --user daemon-reload
systemctl --user restart galene.container
podman healthcheck run galene
podman ps
```

`podman healthcheck run galene` exits 0, and `podman ps` shows `(healthy)`. For a system unit, drop `--user` on the `systemctl` commands.

## Storage driver

Avoid `vfs` — it is very slow for the SQLite WAL workload. `overlay`/`overlay2` (the default) is what you want.

## Pulling from GHCR

**Public images pull anonymously** — no login:

```bash
podman pull ghcr.io/galene-finance/galene:latest
```

Only if pull fails (private package, org policy, rate limits, etc.) run `podman login ghcr.io` with a **classic** personal access token that has `read:packages`. Fine-grained tokens cannot authenticate to GHCR.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Can't bind a port below 1024 as a normal user | `sysctl net.ipv4.ip_unprivileged_port_start=0`, or use a port ≥ 1024. |
| `podman pull ghcr.io/…` fails after a fine-grained login | `podman logout ghcr.io` and pull anonymously, or use a classic PAT with `read:packages`. |

The volume requirement, upgrades, and the cookie behavior match [Docker & Compose](/self-host/docker/). Podman healthcheck setup is in [Healthcheck](#healthcheck).
