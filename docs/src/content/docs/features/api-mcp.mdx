Galene exposes its data two ways: a read-only JSON REST API, and an MCP (Model Context Protocol) server that wraps it for AI assistants. The MCP server talks stdio when a client launches it, or HTTP on the **same host and port as the app** at `/mcp` when an administrator enables it in Settings (default **off**).

## REST API

Nine read-only endpoints under `/api/v1`: summary, accounts, transactions, categories, tags, budgets, scheduled, cashflow, and notifications. All amounts are integer cents (negative = expense); dates are `YYYY-MM-DD`.

`GET /api/v1/accounts` returns each account’s `opening_balance_cents` and `opening_as_of` (null until set) plus ledger `balance_cents` computed as **opening + transactions on/after as-of** (opening is the balance *before* those transactions). After bank sync it may also include `provider_balance_cents` and `provider_balance_as_of` (null for manual accounts or until a sync reports a balance). `GET /api/v1/summary` `balanceCents` uses the ledger rule across all accounts.

Tokens are per-user. Create, use, and revoke them on the [API tokens](/api-tokens/) page — the token is shown once, at creation.

```bash
curl -H "Authorization: Bearer galene_…" http://localhost:3000/api/v1/summary
```

Unauthenticated requests get a JSON `401`.

## MCP in the app image

The main app image (`:app-latest` / `:app-test`) includes the MCP bundle (`mcp-bundle.js`, ~214 KiB) for stdio clients. You do **not** need a separate `:mcp-latest` container for normal installs. HTTP MCP is served by the app itself — no second port.

1. Create an API token (Settings → API).
2. **HTTP (same port as the app):** an administrator turns on **Enable MCP HTTP** under Settings → API (default off). Off means `/mcp` is not live. On serves MCP at `http://<host>:<app-port>/mcp`. Each client sends `Authorization: Bearer <token>` per request. Do not set `GALENE_API_TOKEN` on the app process for this mode.
3. **Stdio (client-launched):** the MCP client starts the bundle itself — no Settings toggle required.

Optional env override: `GALENE_ENABLE_MCP=1` / `0` forces MCP HTTP on or off (same pattern as `GALENE_OIDC_ENABLED`). There is no MCP port or host setting — MCP always uses the app listener when enabled.

### Stdio client config

From a source checkout:

```json
{
  "mcpServers": {
    "galene": {
      "command": "bun",
      "args": ["/path/to/galene/mcp/index.ts"],
      "env": {
        "GALENE_API_URL": "http://localhost:3000",
        "GALENE_API_TOKEN": "galene_…"
      }
    }
  }
}
```

From the app image (stdio session):

```bash
docker run --rm -i \
  -e GALENE_API_URL=http://host.docker.internal:3000 \
  -e GALENE_API_TOKEN=galene_… \
  --entrypoint bun \
  ghcr.io/galene-finance/galene:app-latest \
  mcp-bundle.js
```

(`host.docker.internal` is an example for reaching the app from another container on Docker Desktop; use a URL that is reachable from the MCP process.)

### HTTP client config

After enabling MCP in Settings:

```json
{
  "mcpServers": {
    "galene": {
      "url": "http://127.0.0.1:3000/mcp",
      "headers": {
        "Authorization": "Bearer galene_…"
      }
    }
  }
}
```

Use the same host and port as the app (only port **3000** in compose). Use plain HTTP on localhost or a private network only. Do not expose the app as plain HTTP on a public interface — terminate TLS at the reverse proxy and forward to the app port; `/mcp` is covered by the same proxy rule as the UI.

## Migration from dual-port / `:mcp-*`

Operators who ran MCP on a separate port (ADO-35 default **3001**) or a separate `:mcp-*` container can:

1. Pull a current `:app-*` image.
2. Enable MCP in Settings → API (or set `GALENE_ENABLE_MCP=1`). No need to publish a second port.
3. Point HTTP clients at `http://<app-host>:<app-port>/mcp` (same origin as the UI).
4. For stdio-only clients, switch the client command to the app image entrypoint shown above (or keep launching `mcp/index.ts` from a source checkout).
5. Remove any `3001:3001` / `GALENE_MCP_PORT` / `GALENE_MCP_HOST` compose or Settings leftovers from the app service.

The `:mcp-*` tags remain published for a while as a thin alias of the same bundle so existing stdio client configs keep working. Prefer the app image long-term; a separate MCP container is no longer required.

## Tools

The MCP server exposes: `galene_summary`, `galene_accounts`, `galene_transactions`, `galene_budgets`, `galene_scheduled`, `galene_categories`, `galene_notifications`, and `galene_version`. Tools stay read-only. A missing or unknown token is rejected; delete the token in Settings → API and the next request from that client fails.
