title: Bank sync
description: Import accounts and transactions from SimpleFIN, Plaid, or the demo bank.
---

Galene imports accounts and transactions from bank providers through a common sync interface (Settings → Bank sync). Three providers ship:

- **Demo Bank** — built-in mock with demo accounts and ~3 months of realistic transactions; makes no external calls.
- **SimpleFIN** — the SimpleFIN protocol (SimpleFIN's bridge, or any bank that implements it): you paste a one-time setup token, and Galene claims it once for a long-lived access URL. Setup: [SimpleFIN](/features/simplefin/).
- **Plaid** — live bank accounts through Plaid Link: you pick your bank and log in in Plaid's hosted widget. Setup: [Plaid](/features/plaid/).

Syncs are incremental. When transactions are already imported, each pull asks for rows dated on or after 14 days before the newest one, so a charge that posts under a new id is still in the window. The first sync, with nothing imported yet, uses the provider's default window (about 90 days for Plaid). Imports are deduplicated by provider + external id. A later sync counts a row as updated only when a bank-owned field changed: date, amount, the payee the bank sent, pending state, pending id, or account. Refreshing a pending row's last-seen time does not count. When Plaid sends a statement line, Galene stores that as the payee. Otherwise it stores Plaid's cleaned name. A later sync replaces that payee only when it still matches the last payee the bank sent. A payee you renamed stays, and notes stay when the bank does not send any. When Plaid posts a charge and names the pending id, Galene keeps the posted amount, date, and id, copies category, notes, color, tags, and splits only onto empty posted fields, and deletes the pending row. It does not import that pending row again when the same response already posts it. Two charges are not merged on merchant and amount alone. A pending id that disappeared from the feed still folds into one matching posted row when the match is unambiguous (including grocery auth→adjust within a 15%/$25 amount band). Galene stores each row's pending flag and pending_transaction_id so a later sync can fold by that id across responses, and shows a Pending badge on those charges. When several live candidates look equally plausible, the orphan is queued under Transactions → Sync review (keep both, fold into a chosen row, or dismiss) instead of guessing. Your categorization rules run on new imports. Disconnecting a connection keeps the accounts and transactions already imported.

## Auto-sync

Each connection can auto-sync on a schedule. The server checks every minute and syncs connections whose next sync time has passed; a failed sync backs off to at least an hour. When a Plaid sync updates some institutions and not others, Galene does not use that hour-long backoff. The connection error names each institution that failed and what to do next. See [Plaid](/features/plaid/). Intervals are bounded per provider:

| Provider | Minimum interval | Why |
| --- | --- | --- |
| Demo Bank | 15 minutes | no external API to rate-limit |
| SimpleFIN | 2 hours | the bridge allows 24 requests/day per access, and one sync is one request |
| Plaid | 15 minutes | Plaid rate-limits per Item (15 req/min `/accounts/get`, 30 req/min `/transactions/get`); a sync makes a few calls per linked bank |

## Provider (bank) balance

On each successful SimpleFIN or Plaid sync, Galene stores the institution-reported **bank balance** (signed cents) and an **as-of** timestamp per linked account — SimpleFIN’s `balance` / `balance-date` when present, otherwise Plaid’s current/available balance stamped at fetch time. Demo Bank also reports sample balances.

The Home **Balances** widget and **Settings → Accounts** show **Ledger** (Galene’s computed balance, including any opening-balance anchor) beside **Bank** when a provider balance exists. Manual accounts never show a Bank value. Galene does **not** auto-adjust the ledger to match the bank. On **Settings → Accounts → Edit**, you can apply a **suggested opening** from bank − transactions (user confirm only) — see [Accounts & tags](/features/accounts-tags/). Comparing the two and locking cleared rows is [Reconcile](/features/reconcile/).

Deleting a synced transaction keeps the provider line in a held table (`sync_unimported`) instead of importing it again on the next sync. Reconcile lists those lines as missing from Galene. A pending line that the same response already posts is not held.
